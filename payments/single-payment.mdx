The treasury funds can be used to send payments to an external account. You can request payments to any wallet address on any blockchain, even if the treasury does not have the required tokens to cover the payment—your team can top up the treasury with the required tokens later.

<Check>
  Need to request multiple payments at once? Check the [Proposing Multiple Payments](/payments/bulk-payment) section.
</Check>

<Warning>
  Payment requests can only be created by team members with the [Requestor](/governance/members-and-roles#requestor) role, and they require approval from team members with the [Finance](/governance/members-and-roles#finance) role before they can be executed.
</Warning>

---

## 🔒 Private Payments

Treasuries can create payments to [near.com](https://near.com/) accounts, or directly to public wallet addresses. Both types of payments are executed within the private shard, so they are inherently private.

Payments sent to [near.com](https://near.com/) accounts require the recipient to [log in to near.com](/guides/confidential-payments) to access and withdraw the funds. In this case, the sender appears as the confidential treasury's account on [near.com](https://near.com/).

Payments sent directly to public wallet addresses are also executed within the private shard. In this case, the recipient sees the funds come from the near.com settlement account because they are bridged from the private shard to the public one before being sent to the recipient.

## Requesting a Payment

Navigate to the **`Payments`** section in the left sidebar, then enter the required details: the recipient's **wallet address**, the **token** and **amount** you want to send, and the recipient's **network**.

![Payment request form](/assets/docs/payments/single-payment.webp)

<Check>
  You can create a payment request even if the treasury does not have the necessary tokens. This allows you to request payments, and the team can top up the treasury with the required tokens later.
</Check>

<Note>
  Use the [Address Book](#address-book) to save frequently used wallet addresses and easily select them when creating payment requests.
</Note>

---

## Reviewing the Payment Request

After entering the payment details, review the request before submitting it. You can add a comment to provide more context to the approvers.

![Payment request review](/assets/docs/payments/single-payment-review.webp)

<Tip>
  After the payment is approved and executed, you can generate a [receipt](/payments/handling-requests).
</Tip>

<Warning>
  Verify the blockchain and wallet address before submitting the request, as payments are irreversible.
</Warning>

## Address Book

The address book lets you save frequently used wallet addresses, making it easier to select the correct recipient when creating payment requests.

![Address Book](/assets/docs/payments/address-book.webp)

<Tip>
  Addresses can be linked to multiple blockchains, so you can save a recipient's wallet address once and use it for payments across different networks.
</Tip>

Navigate to the **`Address Book`** section in the left sidebar, then click **`Add Recipient`** to save a new wallet address.

## Frequently Asked Questions

The following questions cover common issues when creating payment requests.

<Accordion title="Can I edit a payment request after submitting it?">
  No, once a payment request is submitted, it cannot be edited. If you need to make changes to a payment request, you will need to delete the existing request and create a new one with the correct details.
</Accordion>

<Accordion title="What if the recipient's wallet address is incorrect?">
  If the payment request is approved and executed with an incorrect wallet address, the funds will be sent to the wrong address and may be unrecoverable.

  Always double-check the wallet address before submitting the payment request to avoid any mistakes.
</Accordion>
